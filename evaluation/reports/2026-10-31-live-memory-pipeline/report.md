# OpenCode 真实自动记忆链路冒烟

- Provider：`opencode`
- 模型：`deepseek-v4.1-flash`
- 数据库：每次运行创建的隔离临时 SQLite
- 普通用户数据库：未写入
- 日期：2026-10-31

本轮通过真实 API 完成了三次受控聊天：

1. 用户首次告诉角色自己在苏州，并提到正在学习手冲咖啡；
2. 用户明确更正为已经搬到杭州；
3. 用户同时询问当前和以前所在的城市。

后台模型从原话中提取候选事实，程序完成逐字证据校验和语义审核，最终观察到：

- 杭州记录为当前有效事实；
- 苏州记录保留为被替代的历史值；
- 角色在对话中即兴新增的手冲经历被保存为 `role_claim`，来源权限为 `character_self_report`，没有覆盖作者角色卡；
- 检索上下文包含杭州当前值，并使用 `fts5_lexical_bge`；
- 第三条真实回答同时包含杭州和苏州；
- 两个记忆后台任务在关闭隔离服务前完成，第三条聊天又排队了 1 个后台任务。

机器可读结果见 [live-memory-pipeline.json](live-memory-pipeline.json)。

## 运行方式

```powershell
D:\Others\Study\Anaconda3\envs\qwen3-im-chat\python.exe -B `
  scripts\smoke_auto_memory_opencode.py
```

脚本只读取本机加密密钥，不回显 Key；所有聊天和记忆数据库均放在临时目录。

## 证据边界

这证明“一条明确更正可以在真实模型中走到提取、审核、存储、检索和最终回答”，不证明提取准确率。它只有一个固定合成场景，最终回答使用确定性短语检查，没有评价自然度，也没有代替完整角色质量测试或独立盲评。
