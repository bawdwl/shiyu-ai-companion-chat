# 拾语项目详细介绍

## 1. 项目概述

拾语是一套面向中文单角色长期陪伴的虚拟角色聊天应用，包含 Android 原生客户端、
Windows 桌面程序和 PC 网页完整环境。项目目标不是制作通用问答助手，而是让用户
创建或导入一个角色，并在持续对话中保持该角色的人格、表达方式、世界设定和共同经历。

当前 `0.22.6` 以 Android `0.19.2` 的成熟聊天行为为基线，同时保留后续版本中已经
验证有价值的工程能力：

- 完整备份与恢复；
- 聊天历史分页；
- 长期记忆证据与用户控制；
- 回复版本、分支和 Checkpoint；
- Prompt Inspector；
- Qwen3-Embedding 语义召回；
- Android 完整版与云端版的独立构建。

## 2. 设计原则

### 2.1 稳定聊天优先

角色聊天质量主要取决于角色档案、近期上下文、世界书和长期记忆是否清晰。拾语避免
在每轮对话中堆叠过多规则，不默认注入心情数值、关系分数或复杂行为树。角色先回应用户
当前内容，再决定是否补充动作、问题或自己的安排。

### 2.2 数据本机优先

聊天记录、角色图片、API Key、长期记忆和 Prompt Trace 默认保存在用户设备。项目方
不运营聊天云数据库，Android、PC 和 Windows 之间也不会自动同步用户数据。

### 2.3 记忆可追溯

长期记忆不是一段不可解释的模型摘要。结构化记忆包含：

- 主体：用户、角色或共同经历；
- 事实键和值；
- 事实类型：事实、偏好、计划、假设、观点、事件或角色自述；
- 来源权限；
- 原始消息编号；
- 逐字证据；
- 生命周期状态和版本关系。

用户可以查看来源、修正、钉住、标记过时、忽略一轮或删除。

### 2.4 平台各自实现，行为保持一致

PC 使用 Python、FastAPI 和 SQLite；Android 使用 Kotlin、Compose 和 Room。
两端共享角色、Prompt、记忆和事件的行为约定，但不强行逐行复制代码。

## 3. 总体架构

```text
Android 完整版 / 云端版
  Compose UI
  ViewModel
  ChatRepository
  Room + FTS4 + 可选 Qwen embedding
  OpenCode Go / DeepSeek / 可选 MNN

Windows EXE
  pywebview
  同一 React 构建产物
  内置 FastAPI 与 Python 后端

PC 网页完整环境
  React + Vite
  FastAPI
  SQLite + FTS5
  可选 BGE / 本地 Qwen / MeinaMix / CosyVoice / Whisper
```

## 4. 角色创建与角色档案

### 4.1 创建流程

用户输入角色灵感后，模型生成结构化角色卡草稿。草稿不会自动保存，而是先进入编辑页，
允许用户检查身份、性格、说话方式、关系、外貌、世界书和知识边界。

角色卡主要字段：

- `description`：角色身份与当前处境；
- `personality`：性格、行为方式和矛盾点；
- `speech_style`：语言节奏、用词和动作表达习惯；
- `relationship`：与用户的当前关系和边界；
- `background`：经历和背景；
- `motivation`：角色自己的目标和顾虑；
- `greeting`：首次对话开场；
- `knowledge_boundary`：时代、世界和知识截止；
- `fixed_facts`：作者确认的稳定事实；
- `worldbook`：世界规则、地点、组织和历史；
- `example_dialogue`：可选语气示例。

### 4.2 正式固定事实

正式固定事实描述“这个角色本身已经确认的事实”，例如：

- 角色是医生；
- 角色来自某个城市；
- 角色与用户是同事；
- 角色长期调查某件事。

只有状态为 `confirmed` 的事实进入 Prompt。`proposal` 是模型生成或用户尚未确认的
提案，只保留在编辑器中。

### 4.3 世界书

世界书描述角色所处世界，而不是角色个人资料。例如：

- 某个门派所在地和组织结构；
- 某座城市的历史；
- 某个势力的秘密；
- 一条世界规则；
- 某个重要地点。

世界书按关键词命中进入上下文。Android 和 PC 都支持查看和编辑世界书；它与聊天长期
记忆分开保存。

## 5. 聊天生命周期

一次聊天请求大致经过：

1. 读取当前角色、近期历史、世界书和结构化记忆；
2. 根据当前用户消息判断是否需要检索更早记忆；
3. 选择相关事实、事件和旧对话摘录；
4. 组装 System Prompt、历史消息和本轮输入；
5. 调用云端或本地模型；
6. 流式展示回复；
7. 保存消息和 Trace；
8. 后台提取新的长期记忆；
9. 视情况更新 Qwen 向量索引。

当前聊天基线保留较紧凑的 Prompt，避免把所有记忆和内部规则同时塞入模型。

## 6. 长期记忆

拾语把记忆分为三层：

### 6.1 近期原始历史

最近若干完整轮次以原文进入模型。它负责承接语气、当前动作、场景和短期指代。

### 6.2 结构化长期记忆

后台模型从对话中提取候选事实，并要求：

- 必须能从原话找到证据；
- 区分用户陈述、角色自述和共同经历；
- 区分事实、偏好、计划、假设和观点；
- 计划不能被改写成已发生事实；
- 角色即兴自述不能覆盖作者角色卡；
- 更正产生新版本，旧版本保留为历史。

### 6.3 旧对话摘录与事件

旧对话摘录用于补充具体语境；事件记录共同经历、约定、取消和完成状态。

## 7. 检索与 Qwen3-Embedding

Android 默认使用 Room、FTS4、中文单字/双字/三字索引、词法关系和确定性排序。

用户可选安装 `Qwen3-Embedding-0.6B-ONNX INT8`：

- 模型约 596 MiB；
- 不进入 APK；
- 1024 维向量；
- 512 Token 输入上限；
- 查询使用 instruction；
- 文档做 last-token pooling 和 L2 normalization；
- 向量按角色、模型版本、记忆 ID 和内容哈希绑定。

检索时，Qwen 语义分数与 FTS4、词法相似度、来源可信度、重要性和时间信号共同排序。
模型未安装、加载失败、索引为空或用户关闭开关时，自动回退到 FTS4。

设置页提供“检测语义检索”，同时检查模型推理、向量索引和现有记忆的抽样语义分数。

## 8. 场景、事件与用户边界

当前版本保留 0.19.2 的场景行为：

- 日常模式不擅自替用户建立现实地点和行动；
- 明确沉浸式角色可以承接已经建立的剧情；
- 场景变化优先来自用户明确表达或前文已经发生的内容。

事件记忆用于记录共同经历和约定，并区分未完成、已完成和已取消。用户明确表达
“不要追问”“不想聊这个”“不要再问”等边界时，相关约束会在后续回复中持续遵守。

## 9. Prompt Inspector

Prompt Inspector 是只读调试界面，用于查看：

- 当前 Provider 和模型；
- Prompt 版本；
- 输入和输出 Token；
- 估算预算；
- 选中的记忆数量；
- 世界书命中；
- 记忆进入上下文的原因；
- 模型耗时。

Trace 不保存完整 Prompt、API Key 或用户图片内容。

## 10. 分支、回复版本与备份

### 回复版本

重答不会覆盖旧回答，而是保存新版本。只有当前选中的版本参与后续聊天和记忆提取。

### 分支

可以从任意消息创建分支。角色卡和世界书共享，聊天、事件、场景和分支记忆独立恢复。

### 备份

ZIP 备份包含：

- Room/SQLite 数据库；
- 角色头像和背景；
- 非敏感设置。

备份排除：

- API Key；
- 加密 Secret 文件；
- 本地模型权重；
- 下载缓存。

恢复前会校验清单、哈希、数据库完整性和 Schema 版本。失败时保留原数据。

## 11. Provider 与模型

当前云端主线：

- OpenCode Go：`deepseek-v4.1-flash`；
- DeepSeek 官方 API：`deepseek-chat`。

两个 Provider 使用独立 API Key。Android 完整版还支持导入 MNN 模型；云端版不包含
MNN、QNN、ASR 或 TTS 运行库。

## 12. 图片与语音

云端版支持云端聊天图片和千问角色图片生成。Android 完整版可导入 Local Dream
SD1.5/QNN 模型进行本地头像生成，并包含本地 ASR 与 VITS 语音运行库。

PC 完整环境支持自行接入 MeinaMix、CosyVoice 2、GPT-SoVITS、MeloTTS 和 Whisper。

模型权重均不进入 Git 仓库。

## 13. Windows 与 PC

Windows EXE 使用 pywebview 加载同一套 React UI，内部启动 FastAPI。发布包不包含
本地大模型、生图模型和完整语音模型。

PC 网页版从源码运行，适合接入 GPU、本地 LoRA、BGE、Diffusers 和完整语音实验环境。

## 14. 工程验证

当前验证包括：

- Python 单元与接口测试；
- 前端状态测试；
- React 生产构建；
- Android 完整版/云端版 JVM 测试；
- Android lint；
- Android APK 构建；
- Windows PyInstaller；
- APK 签名和版本检查；

自动测试不等同于真实设备长期聊天质量评测。真实模型自然度、设备内存和长时间后台任务
仍需持续人工验收。

## 15. 已知限制

- 云端模型输出仍可能重复、过度简短或遗漏细节。
- 长期记忆提取可能漏记或误判，需要用户修正。
- Qwen embedding 在低内存设备上可能加载失败，此时回退 FTS4。
- Android 与 PC 数据不自动同步。
- 世界书检索仍以关键词为基础，复杂跨条目推理有限。
- 项目不承诺替代现实关系或提供专业心理、医疗、法律建议。

## 16. 技术栈

Android：

- Kotlin、Jetpack Compose、Room、WorkManager；
- OkHttp、org.json、ONNX Runtime；
- MNN、Local Dream/QNN、sherpa-onnx（完整版）。

PC/Windows：

- Python、FastAPI、SQLite、FTS5；
- React、TypeScript、Vite；
- pywebview、PyInstaller；
- 可选 Diffusers、Transformers、PEFT、BGE、CosyVoice。
