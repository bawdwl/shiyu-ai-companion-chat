## P1 角色上下文

- Android Room 从 schema 14 无损迁移到 schema 17。
- `characters` 增加 `roleContextJson`，旧角色默认空对象，不覆盖原档案。
- 上下文包含固定事实、示例对话、示例开关、场景、动机、背景、边界、
  稳定目标和互动模式。
- 编辑页提供角色上下文 JSON 入口；保存时进行规范化。
- 生成角色会解析固定事实和示例，模型新增固定事实默认标为 `proposal`。
- 示例默认关闭，只在前两轮最多注入两条。
- 固定事实优先于世界书、长期记忆和角色即兴自述。
- 宋知意和裴既明继续使用逐字固定训练 Prompt，不注入新增上下文。

PC `character_cards.py` 同步支持 `goals`、`use_examples` 和
`interaction_mode`，仍使用完整角色卡，不复制 Android 额外角色。

## P2 自然对话策略

- 新增确定性 `DialoguePolicy`，支持 `LISTEN / DISCUSS / SHARE /
  CELEBRATE / CLARIFY / DISAGREE / CONTINUE / CLOSE / NONE`。
- 默认返回 `NONE`，不额外请求模型，不把普通聊天强制写成脚本。
- 明确“不想听建议”“别追问”时优先降低提问并提供倾听空间。
- 普通回复增加“通常不需要提问，避免连续追问两个问题”的节奏约束。
- 旧 `behavior_rules.json` 仍默认关闭。

## P3 记忆需求与查询扩展

- 新增 `MemoryNeedPolicy`。
- 问候、笑声、简单确认和低信息短句默认不召回长期记忆。
- 明确回忆、指代、更正、边界、计划进展和问句才检索。
- 指代查询使用最近两条用户消息扩展，检索文本不改变用户可见消息。
- Trace 记录 `memory_needed`、原因、扩展来源 ID 和跳过模式。
- Android 仍使用 FTS4 + 确定性词法排序，没有引入端侧向量模型。

## P4 事件记忆与 Open Loops

- Android 新增 `memory_events` 和 PC 结构化记忆库新增同名事件时间线。
- 事件从已经过证据校验的计划和共同事件派生，不增加主聊天 API 调用。
- 事件包含 topic key、摘要、状态、来源消息、参与方和增量时间线。
- 同一事实主题从计划更新到完成时合并为一条事件链。
- 只有当前问题或承接线索与事件相关时才注入。
- 回退、重置和删除角色会清除事件；不会留下孤儿数据。

## P5 当前轮临时情绪

- 新增 `CurrentTurnAffectPolicy`。
- 好消息、困难、冲突、修复和边界事件会在本轮立即影响语气。
- 临时情绪只进入本轮 Prompt，不直接修改信任、熟悉度、温暖或关系阶段。
- 持久状态仍由后台证据任务更新和衰减。

## P6 场景与角色目标

- Android 新增 `scene_states`，PC 从明确对话中重建当前场景。
- 日常模式不自动创建地点，不替用户安排现实行动。
- 只有“我们现在在……”“场景设定在……”等明确语句才进入沉浸式场景。
- “退出剧情/回到现实”会清除当前场景。
- 角色稳定目标属于角色上下文；不自动生成离线生活经历。

## P7 PC 对齐

- 新增 `src/experience_policy.py`，PC 使用相同的对话、记忆需求、临时情绪、
  场景和事件派生策略。
- `prompt_pipeline.py` 使用分层场景、交流倾向和即时反应提示。
- 固定训练 Prompt 保持原样，并在固定 Prompt 分支提前返回。
- PC 事件由结构化记忆库派生，随角色范围清理。
- Windows 桌面端继续复用同一 `src/`，没有新增权重、账号或云同步依赖。

## Android 首页翻页与角色图裁剪

- 首页最新回复视图不再让内部 `LazyColumn` 抢占纵向手势。
- 展开完整聊天历史时暂停无限角色 pager，收起历史后恢复角色切换，
  避免列表滚动与角色翻页同时争抢手势。
- pager 吸附阈值改为中间位置，松手后总是回到最近角色页，不再停在两页之间。
- 首页背景预览使用 1024 长边的独立缓存，减少滑动时的大图解码抖动。
- 本地 Dream 的正方形生成结果会保留为角色原图，不再自动从中间裁成 9:16。
- 生成后先由用户选择 9:16 聊天背景，再从选中的背景中裁 1:1 头像。
- 头像预览和最终保存使用同一组嵌套裁剪坐标，保证预览位置与实际输出一致。
- 所有密度的 `ic_launcher.png` 已移除与画布边缘连通的黑色底色，
  Android 启动画面不再显示图标四周的黑框。

## 已知限制

- 40 场景对比只覆盖两个普通角色，自然度仍需要作者真机连续聊天判断。
- 固定 LoRA 角色不参与新增记忆、状态、场景和事件注入。
- Android 事件页尚未单独提供管理入口，事件目前进入 Prompt 和 Trace。
- P4 事件从已经校验的计划和共同事件派生，不解析复杂多事件剧情。
- 尚未在真实手机和 Windows 用户数据上执行覆盖升级；下一次安装前必须先备份。
