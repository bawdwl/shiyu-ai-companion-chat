# 拾语内部状态与长期记忆优化分析

更新日期：2026-11-11

本文面向架构评审。目标不是证明内部状态“有用”或“没用”，而是说明当前实现、
已经观察到的失败模式、可参考的论文和项目，以及下一阶段应该如何做对照实验。

## 1. 当前实现

Android 和 PC 目前都保存以下持久状态：

- 心情效价 `valence`。
- 心情唤醒度 `arousal`。
- 熟悉度 `familiarity`。
- 信任度 `trust`。
- 温暖度 `warmth`。
- 关系阶段 `stage`。
- 用户明确建立的边界。

后台记忆任务从一段已完成对话中提出 `state_update`，程序再校验证据、限制单次
变化幅度、去重并应用。当前单次幅度上限是：

| 维度 | 单次上限 |
|---|---:|
| Valence | ±0.10 |
| Arousal | ±0.08 |
| Familiarity | ±0.02 |
| Trust | ±0.03 |
| Warmth | ±0.04 |

心情和温暖度会随时间衰减：

- 心情效价半衰期约 18 小时。
- 唤醒度半衰期约 8 小时。
- 温暖度半衰期约 7 天。
- 熟悉度和信任度不会自动衰减。

持久状态通过自然语言进入 Prompt，数字本身不展示给用户。另有“本轮即时反应”
规则，用于好消息、压力、冲突、道歉和边界等当前输入；它只影响当轮，不直接修改
长期状态。

## 2. 真实数据中的问题

以本地完整版角色“姜拂衣”为例：

- 约 386 次角色回复。
- 持久状态只成功更新 7 次。
- 最后一次状态更新是 2026-11-09。
- 修复前当前心情已衰减为“平静”。
- 修复前关系阶段仍然是 2026-11-06 冲突留下的“关系紧张”。
- 熟悉度约 0.246，信任度约 0.284。
- 修复前状态段约 274 字符，约占一次输入 Prompt 的 8–9%。

因此模型每轮仍会看到：

```text
心情平静
关系紧张
仍处在初步了解阶段
还没有建立很深的信任
```

这与最近数百轮持续互动和关系缓和存在明显冲突。状态段每轮都消耗 Token，却可能
让角色持续保持戒备。

问题不是“状态没有进入 Prompt”，而是状态值已经失去时效性和可信度。

## 3. 当前设计的具体缺陷

### 3.1 把四种不同对象混在一起

当前结构同时保存：

1. 短期情绪。
2. 长期关系倾向。
3. 关系事件阶段。
4. 用户边界。

它们的生命周期完全不同：

- 当前心情应持续数分钟到数小时。
- 冲突/修复阶段应持续数小时到数天。
- 熟悉、信任和温暖应持续数周到数月。
- 用户边界不是情绪，不应受衰减影响。

放在同一个 `state_update` 中会互相干扰。

### 3.2 关系阶段会锁死

原逻辑在阶段为“关系紧张”或“关系修复中”时，只要本批没有出现
`conflict` 或 `repair`，就保留旧阶段。正向互动、共同经历和承诺守约都无法推动
阶段恢复。

修复后已经改为：

- 超过 24 小时的紧张/修复阶段自动按当前关系数值回落。
- 正向证据先进入“关系修复中”。
- 再有一条正向证据后回到由熟悉、信任和温暖计算出的阶段。

但这仍是规则修补，不应视作成熟的情感模型。

### 3.3 状态更新依赖脆弱的记忆提取

状态更新与结构化记忆共用后台 JSON 提取任务。姜拂衣的数据中：

- 9 个后台任务因 JSON 截断失败。
- 累计重试 54 次。
- 1 个任务因每日后台预算耗尽而排队。
- 一段时间内游标落后于当前消息。

记忆任务失败时，关系状态也停止更新。因此“内部状态失效”不是独立问题，而是
记忆流水线可靠性问题的一部分。

### 3.4 状态语义过于肯定

“关系紧张”“还没有建立很深的信任”等绝对描述会被模型当作稳定的关系事实。
低置信、过时或只在一段剧情中成立的状态，不应该使用这种强语义。

更合适的描述应带时间、来源和不确定性，例如：

```text
最近一次明显冲突发生在数日前，目前没有新的冲突证据。
近期多次互动以陪伴和共同活动为主。
这些只作为表达倾向，不覆盖角色卡中的稳定关系。
```

### 3.5 缺少评价过程

当前主要根据事件类型直接给出数值变化，没有区分：

- 事件是否符合角色目标。
- 事件由谁造成。
- 事件是否可控。
- 事件是否确定。
- 角色对事件的预期。

情感计算中的评价理论认为，同样是“用户晚归”，如果角色认为用户故意失约、
还是担心用户遇到危险，会产生完全不同的情绪。

### 3.6 缺少可验证的评价指标

现有 A/B 只检查少数固定配对和作者偏好，不能回答：

- 状态是否改善了多轮一致性。
- 状态是否增加重复安慰和机械追问。
- 状态是否让角色做出用户没有授权的亲密升级。
- 状态更新是否准确对应对话证据。
- 长期运行后是否漂移。

## 4. 是否删除内部状态

不建议直接删除全部状态。更合理的决策是：

- 保留“本轮即时反应”，因为它成本低、可控，并与当前输入直接相关。
- 将持久心情降级为短期、低权重的表达倾向。
- 将关系阶段改成带证据、时间衰减和可修复的关系账本。
- 用户边界从情绪状态中独立出来，作为高优先级规则常驻。
- 状态不得覆盖作者确认的角色卡、固定事实和知识边界。
- 对没有足够证据的角色，可以关闭持久状态注入，只使用短期情绪。

也就是说，删除的是“每轮注入一个可能过时的强关系标签”，保留的是经过验证的
短期情绪、长期关系证据和固定边界。

## 5. 建议的目标架构

### 5.1 评价层

输入不只是当前消息，还包括：

- 当前目标和关系阶段。
- 本轮事件类型。
- 事件发起者。
- 是否符合目标。
- 确定程度。
- 是否可控。

评价层输出结构化 appraisal，例如：

```json
{
  "goal_relevance": "high",
  "desirability": "positive",
  "agency": "user",
  "certainty": "confirmed",
  "controllability": "medium",
  "relationship_relevance": "high"
}
```

这些字段不直接展示，而是用于产生情绪和决定是否更新关系。

### 5.2 短期情绪层

建议保留连续维度，但明确生命周期：

- Valence：愉快/不愉快。
- Arousal：平静/激动。
- Dominance：可控/被压迫，可作为下一阶段实验维度。

情绪由评价结果产生，并通过半衰期回到基线。Prompt 只注入一两句自然语言，
不注入数字。

### 5.3 关系账本

不要把“关系阶段”作为唯一真相。建议保存：

- 熟悉度、信任度、温暖度。
- 最近正向证据和负向证据。
- 最近冲突时间。
- 最近修复时间。
- 未完成承诺和共同事件。
- 每个数值的最后更新时间和来源。

关系阶段由这些证据计算，而不是永久锁定。

### 5.4 边界层

边界单独存储并持续有效：

- 称呼边界。
- 亲密行为边界。
- 隐私和追问边界。
- 用户要求永久忘记的主题。

边界不能随时间衰减，也不能被普通正向情绪覆盖。

### 5.5 Prompt 注入策略

建议按以下规则注入：

- 当前情绪明显偏离基线时，注入 1 行。
- 关系阶段最近发生变化时，注入 2–3 行。
- 与当前话题相关的未完成约定/冲突/修复才注入。
- 固定边界始终注入，但限制总长度。
- 没有显著变化时，不每轮重复完整状态段。

## 7. 建议的对照实验

至少比较以下四组：

1. `off`：不注入持久内部状态，只保留角色卡和当前轮规则。
2. `current`：当前实现。
3. `mood-only`：只注入短期心情，不注入关系阶段。
4. `appraisal-relationship`：评价层 + 短期心情 + 时间化关系账本。

固定同一角色、同一组多轮场景、同一 Provider 和生成参数。应覆盖：

- 日常闲聊。
- 过去事实回忆。
- 明确更正。
- 冲突。
- 冲突后连续正向互动。
- 边界设定。
- 长期约定和未完成计划。
- 多日后重新回到旧话题。

评价指标：

- 事实一致性。
- 时间更正准确率。
- 角色人格一致性。
- 机械安慰、重复反问和复读率。
- 越界亲密或不必要戒备率。
- 用户主观自然度。
- 输入 Token 和首字延迟。
- 状态更新准确率与证据支持率。

## 8. 当前已实施的降风险修正

- 经过独立 OpenCode A/B 后，普通角色最终只保留 `off` 行为：不再注入持久心情
  和关系数值。
- 真实对比使用同一 Provider、同一 `deepseek-v4.1-flash`、同一角色设定和 8 轮
  固定场景，分别建立独立角色与会话。场景覆盖计划、事实回忆、冲突、修复、无关
  闲聊、冲突再回忆、用户边界和称呼检查。
- `off` 保住面试时间地点、冲突原因、修复语义和“不要叫娘子”的边界；
  `lightweight` 接近 `off`，但没有稳定可见增益；`legacy` 注入了完整状态，
  却没有改善同一组检查，并存在把旧关系判断带进当前轮的风险。
- 用户边界从情绪状态中拆出，在产品聊天中持续生效。
- 记忆提取可以从截断 JSON 中恢复已经完整的候选对象。
- 旧版因 malformed JSON 失败的记忆任务会一次性重新排队。
- 每批候选限制为 6 条，并优先用户事实、偏好、边界、计划和事件。
- 旧原话摘录从 4 条降到 2 条，单条 Prompt 文本压缩到约 260 字。
- 最多 3 条高置信用户事实/偏好获得独立核心记忆名额。
- Prompt 明确要求相关历史、约定和关系事实应自然承接，不再等用户指出遗漏。
- 关系紧张/修复阶段超过 24 小时会自动按关系数值回落。
- 正向证据可以把“关系紧张”推进到“关系修复中”，再回到正常阶段。
- 边界描述限制长度，避免每轮注入过长旧文本。
- 状态仍只是软提示，不覆盖角色卡和固定事实。
- Turn Trace 新增准备耗时、首字延迟和生成耗时，便于后续区分本地处理与 Provider 延迟。

这些修改先用于降低负作用，不等同于已经完成成熟的评价式情感架构。
