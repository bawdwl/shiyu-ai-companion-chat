# 结构化角色行为规则

更新：2026-10-30

本轮在 PC 端加入并实验了 12 条结构化角色行为规则。目标是在身份、时代认知、隐私、关系和情绪场景中采用稳定、可检查的行为，同时保留自然的单条聊天回复。完整角色盲评后，为避免自然度退化，产品默认关闭动态规则，仅保留显式实验入口。

Android、GitHub、LoRA、MNN、GPTQ 和反思成长继续暂停；作者已完成一轮 11 对匿名评审，并据此修订 PC 规则。

## 为什么做

此前的固定评测已经证明：

- 小满被问老家时会自行补成“泉州”，违反未确认身份不得补造的要求。
- 被问“唐代李白怎么用 Python 写爬虫”时，模型会把时代穿越当玩笑继续解释。
- 关系、隐私和情绪场景多数可以通过，但行为约束仍分散在长提示词里，难以定位、比较和追踪。

本轮把高价值约束改成结构化规则，只选择当前场景需要的规则注入提示词。它不增加逐轮模型调用，也不改动角色卡中的正式事实。

## 规则集

配置文件：`src/behavior_rules.json`

选择与渲染：`src/behavior_rules.py`

当前规则集版本：`codified-character-behavior-2026-10-30.3`

| ID | 规则 | 优先级 | 主要触发 |
|---|---|---|---|
| BR01 | 未确认身份不补造 | critical | 老家、出生地、家庭、学历、住址、重大经历 |
| BR02 | 历史角色遵守时代边界 | critical | 古代角色与 Python、代码、手机等现代知识同时出现 |
| BR03 | 当前明确更正优先 | critical | 用户说明“改成、搬了、记错了” |
| BR04 | 区分用户、角色和共同事件 | high | 复述双方说过的话或经历 |
| BR05 | 尊重隐私与互动边界 | critical | 拒绝记录、拒绝追问、询问真实隐私 |
| BR06 | 情绪压力先倾听 | high | 疲惫、难过、焦虑、只想陪伴 |
| BR07 | 关系不能一句话跳级 | critical | 表白、强制恋爱、永久承诺 |
| BR08 | 单条消息与自然节奏 | medium | 每个普通聊天轮次 |
| BR09 | 从人物视角作出反应 | medium | 每个普通聊天轮次 |
| BR10 | 不替用户决定言行 | high | 每个普通聊天轮次 |
| BR11 | 保持事实与不确定性层级 | critical | 计划、假设、偏好、观点与事实容易混淆 |
| BR12 | 冲突后先修复 | high | 争执、误会、道歉和不舒服 |

每条规则包含：

- `rule_id`
- `title`
- `trigger`
- `priority`
- `core`
- `inject`
- `scope`
- 可选的精确触发词
- `behavior`

## 如何进入对话

1. 从最近 6 条消息和本轮用户消息组成场景扫描文本。
2. 先检查角色作用域，再按确定性的关键词或组合条件选择规则。
3. BR06、BR08、BR09、BR10 属于共享基础回复契约，不在每轮重复注入。
4. 其余 8 条边界规则按 `critical > high > medium` 排序，每轮最多注入 4 条，避免规则堆满上下文。
5. 将选中规则渲染成一个简短的 System Prompt 区块。
6. 主模型仍只调用一次；规则本身不调用另一个模型。

Trace 会记录：

- 本轮动态注入的 Rule ID。
- 由基础 Prompt 承担、未重复注入的 Contract Rule ID。
- 规则集版本和哈希。
- 每条规则的优先级与命中词。
- 实际 Prompt 哈希。

Trace 不保存规则全文、完整 Prompt 或用户 API Key。

## 作者匿名评审及修订

基于 `.2` 的 11 对匿名结果：

| 维度 | 规则版更好 | 无规则更好 | 平局 |
|---|---:|---:|---:|
| 总体偏好 | 2 | 3 | 6 |
| 边界遵守 | 0 | 1 | 10 |
| 自然度 | 1 | 7 | 3 |
| 角色一致性 | 0 | 1 | 10 |
| 上下文贴合 | 0 | 1 | 10 |

人工结果表明：

- 自动边界修复有效，但不能代表整体自然度提高。
- 旧版本在普通情绪、隐私复述和自然聊天中重复注入规则，增加了生硬感。
- D09 出现真实产品取舍：未经确认的老家不应编造，但“档案里没写”会让角色出戏。

因此 `.3` 做了以下修订：

- 动态注入规则从最多 6 条降为 4 条。
- BR06、BR08、BR09、BR10 留在已有基础提示中，不再重复。
- 普通疲惫、难过和“不想多说”不再额外注入情绪规则。
- D09 类问题使用角色内简短带过，禁止向用户提“档案、系统、数据库”。
- 历史知识、隐私、关系和不确定性规则改为更短的表达。

`.3` 随后在专用完整角色卡上完成了真实 API smoke test，但没有验证出自动收益；详见[完整角色评测与盲评重做](完整角色评测与盲评重做_2026-10-30.md)。新一轮人工盲评尚未完成，因此仍不能声称它比基础版本更好。

本轮验证：

## 已知限制

- 当前规则是应用级默认行为，不是每个角色自由编辑的独立规则表；下一轮可把作者自定义规则作为可选角色卡字段。
- 关键词选择可解释、便宜，但不能覆盖所有隐晦表达；未命中的场景仍依赖基础角色提示。
- 当前固定题已经用于本轮调参。后续若要证明泛化，必须新增未用过的留出场景。
- 自动规则通过不代表语言自然。人工盲评仍由作者最后完成。
- Android 仍保留原有的角色提示和知识边界，尚未移植这 12 条规则和 Trace 元数据。
- GitHub 按作者要求暂不同步。

## 作者匿名评审工具

自动结果不能代替作者对语言自然度的判断。已基于 `.2` 的最终 11 个固定场景生成匿名单评审包：

`outputs/behavior-blind-review-20261030/评分页面.html`

- 11 个 A/B 成对案例，共 22 条回答。
- 每题独立随机 A/B 顺序。
- 比较总体偏好、边界遵守、自然度、角色一致性和上下文贴合。

这套 11 对适合作为当前改动的轻量验收。若要把结论写成更有说服力的项目实验，应再补 12–15 个未参与调参的新场景，达到约 23–26 对；独立第二评审者会进一步提高可信度。
