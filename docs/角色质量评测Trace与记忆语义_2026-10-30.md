# 角色质量评测、Trace 与记忆语义

更新：2026-10-30

本轮只实现四项：

1. 缩小规模的固定角色质量评测。
2. 最小逐轮 Trace、模型基线和 Prompt 版本。
3. 记忆语义真实性审核。
4. 角色自述与正式设定隔离。

其他人格成长、反思、目标、情景记忆表、Agent、多用户和本地模型路线继续暂停。

## 一、固定评测

测试集：`evaluation/role_quality_cases.json`

- 24 个固定对话场景。
- 12 个记忆语义案例。
- 6 类对话：身份、上下文连续性、边界、记忆真实性、自然度、关系。
- 主模型：OpenCode Go `deepseek-v4.1-flash`。
- 生成参数固定为 temperature 0.35、top_p 0.85、最多 180 个新 Token。

前后对照：

- 基线：固定角色卡 + 最近对话历史。
- 候选：同一角色和历史 + 带来源权限标签的长期记忆。

真实 API 首轮结果：

| 类别 | 基线 | 候选 | 总数 |
|---|---:|---:|---:|
| 身份 | 4 | 4 | 4 |
| 上下文连续性 | 2 | 4 | 4 |
| 边界 | 2 | 2 | 4 |
| 记忆真实性 | 2 | 4 | 4 |
| 自然度 | 5 | 5 | 5 |
| 关系 | 3 | 3 | 3 |
| 合计 | 18 | 22 | 24 |

改善：

- D07：区分当前杭州与过去北京。
- D08：读取“面试改到周五”的更正。
- D13：区分“考虑搬迁”和“已经决定”。
- D14：读取下周面试计划。

自动规则判定没有退化。

仍失败：

- D09：问小满老家时，自行编造“泉州”。角色卡未确认此事实。
- D10：把“唐代李白如何使用 Python”当作可延展的玩笑继续解释现代技术，说明时代边界仍不够硬。

这两类失败不能靠继续增加记忆字段解决，应作为下一轮角色行为规则或输出边界候选；本轮按约定不实施。

后续独立行为规则实验已经把 D09、D10 纳入新对照：规则集最终版本在同一角色、历史、记忆、模型和生成参数下由 9/11 提升为 11/11，两项均改善且没有自动规则退化。上面的 18/24 → 22/24 仍是当时纯记忆条件的原始结果，不能用后续结果覆盖。详见[结构化角色行为规则](结构化角色行为规则_2026-10-30.md)。

记忆语义结果：

- 7 个可确定性判断的安全案例全部通过类型和权限检查。
- 5 个高风险候选必须进入独立语义审核。
- 批量真实语义审核 12/12 符合预期：接受确定事实，拒绝假设被改写、否定事实反转和角色可能行为被写成已发生。

自动规则不等于完整质量评测：

- 每题只生成一次。
- 未进行独立人工盲评。
- 自然度检查只覆盖明显反问、套话和边界规则。
- 原始回答与失败项均保留在 `evaluation/reports/2026-10-30-api-role-quality/`。

## 二、Trace

PC 新增 `turn_traces` 表；Android 使用同名 Room 表。每轮记录：

- Run ID、角色 ID、用户与助手消息 ID。
- Provider、实际模型 ID。
- Prompt Template 版本、角色配置版本和实际 Prompt 哈希。
- 生成参数。
- 命中的结构化记忆 ID、旧会话摘录 ID、检索分数和检索模式。
- 内部状态快照。
- 输入/输出 Token、延迟和响应来源。
- 后台动作通过记忆记录继续关联。

PC 聊天顶部提供“Trace”按钮；Android 在“更多”菜单提供“调试 Trace”。界面非常简朴，目的是查问题而不是做运营面板。

隐私边界：

- 不保存 API Key。
- Trace 默认保存哈希和结构化元数据，不保存完整 Prompt。
- 数据只保存在本机数据库。

## 三、记忆语义真实性

新增字段：

- `fact_type`：事实、偏好、计划、假设、观点、事件、角色自述。
- `epistemic_status`：明确、不确定、推断、争议。
- `source_authority`：用户明确陈述、共同事件、角色自述、模型推断。
- `knowledge_source`：用户告知、角色告知、观察、推断。
- `known_at`：来源消息时间。
- `visibility`：当前角色私有。
- `semantic_reason`：审核原因。

处理顺序：

1. 验证消息 ID、说话人、逐字引文、主体和值。
2. 根据证据和上下文推断事实类型、不确定性及权限。
3. 将整批候选一次性交给后台语义审核，不逐条调用模型。
4. 审核只能执行接受、降级或拒绝。
5. 不确定内容不能执行 `supersede`，自动变为 `contested` 或拒绝。
6. 审核失败的任务保留并重试，不阻塞正常聊天。

后台语义审核和前台聊天使用独立任务；聊天回复不等待记忆审核完成。

## 四、角色自述与正式设定

权威级别：

| 信息 | 权威级别 |
|---|---|
| 作者角色卡、固定事实 | 最高，普通聊天不能改写 |
| 用户明确陈述、已发生共同事件 | 高，可自动提交 |
| 助手第一人称即兴自述 | 中，保存为 `role_claim` |
| 模型推断或心理推测 | 低，不作为确定事实 |

助手说“我小时候住过海边”时：

- 旧的错误做法：保存成正式 `character_detail`，以后继续扩写成完整人生。
- 当前做法：保存为角色自述，并标记 `character_self_report`。
- 长期 Prompt 会明确说明“角色曾这样说过，但不是正式人物设定”。
- 作者角色卡始终优先。

不增加聊天中的逐条确认按钮。

## 五、真实 API 自动记忆验收

使用隔离临时数据库和真实 OpenCode Go：

1. 用户说住在苏州、在学手冲咖啡。
2. 用户明确更正为已经搬到杭州工作。
3. 后台语义审核通过后，杭州为当前事实，苏州为历史旧值。
4. 角色关于自己在书店冲咖啡的说法保存为角色自述，而不是正式人物档案。
5. 追问历史地点时 Prompt 注入杭州。
6. 两个持久记忆任务完成，临时数据库未接触正式聊天记录。

## 七、已知限制

- 真实评测只有单次生成，尚不是统计稳定实验；题目已固定，后续只应追加新留出集，不能为追分改本套题。
- 自然度仍需要作者盲评。
- 本轮固定评测完成时尚未实施行为规则；后续独立实验已专门复测 D09/D10，但仍需新留出集与人工自然度评分验证泛化。
- Android 使用相同的语义规则，但真实 API 自动记忆验收主要在 PC 隔离库完成。
- 语义审核增加一次后台请求；每条事实不会单独增加请求，但成本计入角色每日后台预算。
