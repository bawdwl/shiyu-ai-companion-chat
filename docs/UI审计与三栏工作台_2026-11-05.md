## 审计发现

- 原聊天页只有“左侧导航 + 聊天”两栏，角色资料只能进入弹窗查看。
- 首页主视觉占用较高，角色卡首屏能见度不足。
- 创建角色与设置仍以单一弹窗承载长表单，信息密度过高。
- 部分图标按钮只有视觉符号，缺少统一的可访问名称。
- 角色头像和卡面没有显式宽高，异步加载可能造成布局位移。
- 窄屏聊天没有可靠处理右侧信息区，标题栏与输入区可能被最小内容宽度撑开。
- 模态框没有统一处理 Escape、焦点循环和关闭后的焦点恢复。
- UI/UX Pro Max 的自动结果推荐高饱和紫粉配色，与品牌和用户要求冲突，因此被人工覆盖。

## 本轮实施

- 聊天页改为三栏：导航、聊天、角色信息。
- 右侧角色栏显示立绘、简介、对话数、当前有效记忆和当前模型。
- 1180px 以下右侧栏变为抽屉；768px 以下默认关闭。
- 375px 聊天页保持单列，不产生横向滚动。
- SVG 图标统一为同一线性风格。
- 模态框支持 Escape、Tab 焦点循环与关闭后焦点恢复。
- 图片补充宽高，异步状态使用 `role="status"`。
- 增加跳过导航链接和显式键盘焦点样式。

## 仍需推进

- 将创建角色、设置和记忆从长弹窗迁移成独立工作区或分步页面。
- 消息列表达到 100 条以上时接入虚拟列表。
- 增加真正的深浅主题切换和用户偏好持久化。
- 图片生成尚未有 PC 后端能力，当前设计只预留设置入口，不应做无法执行的页面。
