# 音色标签与自定义音色说明

日期：2026-11-04

## 官方实际提供的信息

拾语 Android 当前使用 Kokoro v1.1-zh INT8 中文模型及 sherpa-onnx
`voices.bin`。

Kokoro 官方模型卡说明：

- 模型通过训练加入 100 个中文说话人；
- 另有 Maple、Sol、Vale 三个英文女声；
- 合计 103 个音色；
- 官方公开的说话人标识采用 `zf`（中文女声）、`zm`（中文男声）、
  `af_maple`、`af_sol`、`bf_vale` 等命名；
- 官方没有为全部 103 个音色提供“温柔、高冷、活泼、御姐、正太、
  沙哑、苍老”等性格或听感标签，也没有公开统一的主观试听评分。

因此，不能把“编号 058 等于御姐音”这类猜测写成官方属性。

## 可以可靠实现的部分

1. 开放全部 103 个音色，并允许逐项试听。
2. 保存每个角色选中的音色编号。
3. 根据官方编号、语言和已知性别前缀做基础筛选。
4. 由作者或测试人员试听后，为音色添加“拾语自定义标签”，并明确标注
   这些标签不是 Kokoro 官方标签。
5. 角色创建后，根据角色性格、说话方式和用户偏好的标签返回候选音色，
   仍由用户试听确认。
6. 支持收藏常用音色，并用“最近使用/收藏/试听历史”减少在 103 项中查找。

## 不能仅靠标签直接生成新音色的原因

Kokoro 的每个音色是一个预先训练好的 style embedding，不是几个可以
直接从“温柔程度”“高冷程度”解释的旋钮。模型本身不理解中文标签，也
不会因为输入“温柔 + 御姐”就自动生成一个稳定的新说话人。

如果直接根据标签随机改动 embedding，可能得到：

- 音色不稳定；
- 字音、音高崩坏；
- 同一角色每次生成声音不同；
- 难以复现，也无法解释版权和来源。

所以第一版不提供“标签一键凭空造音色”。

## 可实验的简化方案

Kokoro 官方 Python 推理接口支持把多个 voice tensor 取平均，也支持直接
传入自定义 voice tensor。理论上可以增加“音色融合”实验：

1. 用户试听并选择 2–4 个基础音色；
2. 调整每个基础音色的比例；
3. 应用对 style embedding 做固定权重平均；
4. 生成一个固定的一人 voice 文件；
5. 先试听，再由用户决定是否保存为该角色的自定义音色。

这是对已有音色的混合，应标为“实验性混音”，不能声称是 Kokoro 官方
支持的新人物，也不能只凭“温柔”等标签保证结果。当前尚缺一轮真机听感和
跨设备稳定性验收，因此未把它加入生产角色设置。
