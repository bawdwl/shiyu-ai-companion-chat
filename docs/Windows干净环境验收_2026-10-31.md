# Windows 干净环境验收

本轮建立了可重复的 Windows API-only 验收流程。它解决的问题是：旧安装脚本把开发机的 Anaconda 路径写死，且总依赖文件包含本地 Qwen、语音、训练和图像库，不适合只想运行云端角色聊天的新机器。

## 建议环境

- Windows 10/11 x64；
- Python 3.11；
- Node.js 24；
- pnpm 11；
- 可访问 OpenCode Go 或 DeepSeek API。

本地 Qwen、Whisper、GPT-SoVITS、MNN、GPTQ、LoRA 和 MediaPipe 均不属于本轮 API-only 安装门槛。

## 安装

```powershell
conda create -n shiyu-chat python=3.11 pip -y
conda activate shiyu-chat
python -m pip install -r requirements-api-windows-py311.txt
.\scripts\setup_secret_runtime.ps1 -Python python
pnpm --dir frontend install --frozen-lockfile
```

`setup_secret_runtime.ps1` 现在接受任意 Python 路径，并把 `cryptography` 安装到项目本地 `outputs/secret-runtime`。它不再写死开发机的 `D:\...` 路径。

## 一键验收

```powershell
.\scripts\verify_clean_windows.ps1 -Python python
```

如需同时安装 API-only 依赖：

```powershell
.\scripts\verify_clean_windows.ps1 -Python python -Install -InstallProfile api
```

默认安装配置不会下载 PyTorch、模型权重或语音模型。`-InstallProfile full` 仅供需要历史本地模型链路的环境使用。

脚本执行：

1. Python 版本和 `pip check`；
2. API、图像和 Uvicorn 导入；
3. 项目内 `cryptography` 运行时导入；
4. Python 全量测试；
5. 前端状态测试；
6. React 生产构建；
7. 使用临时数据库启动隔离 API；
8. 验证初始无默认角色；
9. 创建自定义角色并主动开场；
10. 用确定性 Provider 完成一次聊天；
11. 重启后确认历史和加密 Key 仍存在；
12. 写出 JSON 与 Markdown 报告。

## 启动

只启动文字和云端 API：

```powershell
python launch_app.py --provider opencode --speech-provider off --asr-provider off
```

然后访问 <http://127.0.0.1:8000/ui/>，在设置中选择 OpenCode Go 或 DeepSeek 并填写 Key。Key 不会由接口返回给浏览器。

## 验证边界

本次验收在本机环境执行，不能冒充另一台全新电脑的安装证明。真正的全新机器验收仍需复制一个新目录、创建新环境、从零安装并运行同一脚本。

自动化首次聊天使用确定性 Provider，用来证明本地系统链路，不消耗付费 API。发布前仍需要使用者填写真实 Key，完成一次人工文字聊天、创建角色、记忆纠错和重启恢复。
